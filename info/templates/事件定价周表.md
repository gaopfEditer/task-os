# 事件定价周表模板（深度 / 长文）

- 适用形式：深度（长文）
- 适用渠道：X 长推（超过 280 加权字符需 X Premium）/ 币安广场长文；可另备 ≤280 短版 + 跟帖
- 栏目：事件定价
- 数据：只用 sources.md MKT-01「交易观察员已核事件表（trading-watch）」的 *_YYYY-MM-DD.csv 已核表；只用表里已有的数字，不改价位，不补样本，不做推算（不写平均数、中位数）
- 用法：复制到 topics/C-YYYYMMDD-NN-短标题/draft.md 的「正文」里，按下面五段填写；段落顺序和标题不改

---

## 1. 标题、窗口、数据截止、样本

```text
事件定价周表 #N（{事件类型}篇）
{一句话副标题：只描述数据，不写方向}

· 窗口：YYYY-MM-DD 至 YYYY-MM-DD（UTC+8）
· 数据截止：YYYY-MM-DD HH:MM（UTC+8）（取 CSV 的 price_now_time_utc8；多个时间写区间）
· 样本：n={行数}（交易观察员已核{事件类型}表）
```

## 2. 主表

列固定：币种｜{事件}时间（UTC+8）｜占流通 %｜{事件}前 7 天涨跌｜{事件}后涨跌｜同期相对 BTC（pp）

- 数字照 CSV；涨跌幅四舍五入保留 2 位小数，并在来源段写明。
- CSV 时间为 UTC 时换算成 UTC+8，并写明原时区；已是 UTC+8（列名 *_utc8）时写「原表即 UTC+8」。
- CSV 为空的格写「—」，不补。
- 正文用纯文本行（X/币安广场不渲染 markdown 表格），配图用 markdown 表格作图源。
- 主表下加一行「读表」：说明「事件后涨跌」到哪个时刻、观察时长是否不同、「相对 BTC」= 事件后涨跌 − 同期 BTC 涨跌（pp）。

```text
【主表】币种｜{事件}时间（UTC+8）｜占流通｜{事件}前 7 天涨跌｜{事件}后涨跌｜同期相对 BTC
{TICKER}｜MM-DD HH:MM｜x.xx%｜+x.xx%｜-x.xx%｜+x.xxpp
……

读表：……
```

## 3. 表里能看到的（2–3 条）

- 只描述表里的数：涨跌各几个、最高/最低是谁、占流通 ≥5% 的几个里各几涨几跌。
- 不归因、不外推、不写平均数/中位数等派生统计、不做「前涨后跌」类交叉规律。
- 结论句只写「这一期样本里看到什么」，并提醒单期样本不能当规律用。

```text
【表里能看到的】
1. ……
2. ……
3. ……

{结论句}
```

## 4. 同一个{事件}，几个数

- 选 1 个本期各平台口径不一致的案例（时间、数量、占流通等）。
- 两边并列写，各带链接；找不到的链接写【待核】。
- 写清本表采用哪种口径、为什么（通常：已核表按该口径记录、涨跌从该时刻起算）。
- 不评价平台好坏，写「两家口径不同，不代表哪一家有误」；差异原因没核过就写「本表没有核对」。
- 本期没有冲突案例时，写「本期未见口径冲突」，保留小节标题。

```text
【同一个{事件}，几个数：{TICKER}】
· {平台 A} 口径：……
· {平台 B} 口径：……
{采用哪种、为什么}
```

## 5. 来源与固定脚注

```text
来源
{事件}：{unlock_source / 对应来源列里的平台} {链接}
价格：{price_source 列里的价格源}；BTC 基准为 Binance BTCUSDT。涨跌幅四舍五入保留 2 位小数。

单周样本 n={行数}，事后统计，不是交易信号，不构成投资建议。
```

## 配套要求
- 配图：1 张主表图（只写方案，不在 draft 阶段生成），涨跌只用 +/- 号，不用红绿和箭头；底部放来源条和固定脚注。
- 字数：按 X 加权计数（汉字/全角 2，链接 23）；超过 280 注明「X 长推，需 Premium」，或另给 ≤280 短版 + 跟帖。
- research.md：记录 CSV 行数、列名、时区、截止时间、快照路径（存 sources/），与前后期/其他选题的币种重叠情况。
- review.md：保留「发布后 24 小时互动数据（基线）」一节，发布后填。
