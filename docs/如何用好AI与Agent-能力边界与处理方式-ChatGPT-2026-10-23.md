# 如何用好 AI 与 Agent：能力边界、痛点与处理方式（ChatGPT 版）

> 来源：ChatGPT 对话归档（2026-10-23），分享链接：https://chatgpt.com/c/6adabaa7-45f4-83ec-abfe-5e9d71f098b1

## 开宗明义

真正要研究的，不是如何写出一份漂亮的提示词，也不是如何搭建一个看起来很完整的 Agent 流程，而是一个更根本的问题：

**如何理解 AI 的工作机制、能力边界和失效方式，并形成一套能在真实问题中反复使用、能够自我纠错的工作方法。**

痛点并不是孤立的。语义不清、指令冲突、模型能力不足、工具不够、答案不知道何时结束，以及 Agent 无法形成有效闭环，属于一套相互关联的问题。

建议把研究分成若干核心层次。最终目标不是记住一堆技巧，而是形成判断方法：遇到问题时，知道应该怎么用 AI、什么时候不能信任它、何时需要更换方法，以及如何判断事情真的做完了。

---

## 一、整体认知：你面对的不是一个问题，而是一套系统

| 层 | 问题 |
|----|------|
| 第 1 层：目标与问题定义 | 我要解决的究竟是什么问题？什么结果才算有用？ |
| 第 2 层：语言与指令表达 | 如何把真实意图、约束、背景和验收标准表达给 AI？ |
| 第 3 层：模型能力与认知边界 | AI 能推理到什么程度？知道什么、不知道什么？什么时候会出错？ |
| 第 4 层：工具与执行环境 | 模型是否能获得所需信息、操作系统、访问文件并完成任务？ |
| 第 5 层：验证与完成判定 | 结果是否正确、是否满足目标、是否还有未解决的关键问题？ |
| 贯穿全程：反馈、修正与闭环 | 发现错误后，判断问题出在哪一层，针对性修复，而不是一味增加提示词长度。 |

这五层是**研究框架**，不是 AI 内部必然按此顺序运行的流程。真实任务中它们会反复交互。

三个概念不能混为一谈：

- **AI 的能力上限**：即使问题描述清楚、工具齐全，它仍然可能做不到。
- **AI 的实际表现**：在某次任务、某种提示和某个上下文里，它实际做到了什么。
- **AI 的可验证性**：你有没有办法判断它做对了。

## 二、第一层：语义不明、指令不到位、约束冲突

Prompt 优化只是一部分。更核心的是：脑子里的问题经过语言表达后，能否让 AI 正确理解；理解后，是否知道应该优先满足什么。

### 1. 把三种问题分开

| 问题类型 | 典型表现 | 真正需要解决的事情 |
|----------|----------|--------------------|
| 目标不清 | 回答了很多，但不是你真正想解决的问题 | 明确目标和使用场景 |
| 指令不清 | AI 不知道范围、深度、受众或交付形式 | 补充必要信息和验收标准 |
| 约束冲突 | 既要全面又要极短，既要确定结论又不允许做任何假设 | 确定优先级、允许的折中和不可违反的限制 |

更好的做法不是机械增加细节，而是给出**相对明确的取舍原则**（例如：以实际解决问题为目标，优先分析最常见、影响最大的失效原因；明确尚未覆盖的内容，不追求无法保证的绝对完整）。

### 2. 不要试图一次性把所有想法表达清楚

人的思考常在表达过程中才发现真正想问什么。协作更适合迭代：

1. **探索**：先表达问题、困惑、猜测，不急于最终指令。
2. **外化**：让 AI 整理成问题清单、概念结构、已知事实和待验证假设。
3. **对照**：检查理解，指出遗漏、误解和新思路。
4. **收敛**：明确真正要解决的问题、优先级和验收标准，然后执行。

探索阶段不要过早要求最终答案，以免过早收束方向。

### 3. 文字与语音

- **语音**：适合快速倾倒想法、描述经历、提出尚未成形的问题。
- **文字**：适合精确比较、检查条件、审阅推理、管理分支与修订。

建议混合：语音倾倒 → AI 整理成可编辑问题树（先不回答）→ 文字作基准修订 → 再进入分析。

可用指令（探索阶段）：

> 我现在处于问题探索阶段，不要急于给最终答案。请先整理：1) 真正想解决的问题；2) 事实 vs 猜测/感受；3) 问题分支；4) 歧义、矛盾或信息缺失；5) 值得探索但尚未想到的方向。保留原意，不要把不确定变成确定结论。整理后先让我检查再分析。

### 4. 何时追问、何时自己补全

- 缺失会改变结论 → 优先澄清。
- 只影响表达形式 → 合理默认值继续。
- 多种理解 → 先列主要解释并比较影响。
- 探索本身是目标 → 不必一开始澄清完所有问题。

原则：**只有当歧义足以改变决策、产生重大风险或导致返工时，才值得优先消除。**

## 三、第二层：模型能力、工作机制与能力边界

要回答：为什么有时聪明有时犯低级错误？为什么换问法/模型/对话结果不同？如何知道答案值得信任？

### 1. 工作方式：不要神秘化

大语言模型粗略理解：根据当前输入文本、上下文和参数，计算接下来可能生成什么，并通过连续生成形成回答。现代模型还可能有推理训练、视觉、工具调用等。

它不是简单搜索引擎，也不是天然拥有完整事实数据库的知识系统。因此可能：会解释原理却不知今天发生了什么；能生成正确代码却未真正运行；论证完整但关键前提出错；能承认不确定，也可能对错误结论过度自信。

### 2. 能力边界五类

| 类型 | 表现 | 应对 |
|------|------|------|
| A. 知识边界 | 不知事实、过时、概念混淆 | 检索最新来源、原始文档、核对关键事实 |
| B. 推理边界 | 多条件/长链条/精确一致性出错 | 拆分子问题、计算或执行工具、验证中间结果 |
| C. 上下文边界 | 忽略长对话细节、混淆版本要求 | 维护任务状态、关键约束、事实来源和待办 |
| D. 工具与行动边界 | 知道怎么做却无软件/文件/权限 | 区分「建议」与「实际完成」，确认工具返回 |
| E. 可靠性与判断边界 | 遗漏风险、相关当因果、证据不足却确定 | 反例检查、证据要求、独立验证、风险阈值 |

不能把所有失败都归因于模型：也可能是问题定义、资料、工具、约束或验收标准问题。否则会陷入「不断改 Prompt 却没解决真正问题」。

### 3. 表现不好时的诊断表

| 观察到的问题 | 首先检查 | 下一步 |
|--------------|----------|--------|
| 回答偏题 | 目标是否定义清楚 | 重述问题和成功标准 |
| 漏掉关键要求 | 约束是否可见、是否冲突 | 明确优先级并逐项验收 |
| 事实错误 | 是否需要实时或原始资料 | 搜索、引用、交叉核对 |
| 推理不稳定 | 是否过长或复杂推理链 | 拆解、计算、验证 |
| 不断重复废话 | 是否没有明确决策问题 | 要求差异、证据和结论 |
| 无法实际操作 | 是否缺少工具或权限 | 提供文件、连接工具或换环境 |
| 答案始终无法定稿 | 是否缺少完成条件 | 定义必须满足的条件与停止标准 |

仍无效 → 换模型、换工具，或交给人工，不要无限追加指令。

## 四、第三层：能力边界与「回答完整」

### 1. 「完整」的三个含义

| 层次 | 含义 | 风险 |
|------|------|------|
| 形式完整 | 有标题、结构、步骤、总结 | 结构完美却未解决问题 |
| 问题完整 | 覆盖关键事实、约束、分支、风险和判断依据 | 可能正确但仍不知如何应用 |
| 任务完整 | 达到约定实际目标并通过验证 | 知识题可能到问题完整即可；开发/自动化/数据往往要任务完整 |

三者不能相互替代。

### 2. AI 如何收束答案？

常见误解：模型通常没有一个能严格证明「已彻底完整」的内部判定器。

收束受：你的问题与要求、对话上下文与答案结构、训练中的回答模式、产品指令/长度限制/任务配置、工具结果与验证步骤、是否要求继续研究或最终结论等影响。

**答案结束是一种生成行为；任务完成是一种需要依据标准进行的判断。** 这是两件不同的事。

### 3. 主动控制完整性（五步）

1. 检查目标：是否解决最初问题？差距在哪？
2. 检查覆盖面：是否遗漏影响结论的关键因素/分支/前提？
3. 检查证据：事实 / 推断 / 假设？关键结论能否核实？
4. 检查反例：什么情况下结论失效？竞争性解释？
5. 检查可执行性：是否知道下一步？是否有可验证结果？

可用指令：

> 请不要直接扩写。先对照最初目标审查现有回答是否足以解决问题。分别检查：已解决；尚未解决但会影响结论；可能遗漏的关键分支；缺乏证据或仍属假设；哪些补充有必要、哪些只是增加篇幅。明确判断：是否足以支持下一步决策或行动？足够则停止并总结；不足则只补影响最大的缺口。

### 4. 何时停止研究（四项）

- 目标达到
- 关键证据足够（与风险匹配）
- 剩余不确定性可接受（已记录）
- 继续研究的价值有限（预计不显著改变结论或下一步）

**完整性不是内容的绝对数量，而是当前任务的关键不确定性是否已被处理到足够程度。**

## 五、第四层：Agent 怎么工作？

模型层主要解决「如何理解和回答」；Agent 层关注：如何把目标转化为一系列行动，并依据真实反馈持续推进，直到达到完成条件。

Agent 不是把 Prompt 写得更长，也不是在回答中列十个步骤。

### 1. 从普通模型到 Agent 的关键变化（抽象）

目标与完成条件 → 规划与任务分解 → 执行与工具调用 → 观察真实结果 → 验证与决策 →（未达标则回规划/执行）

真正重要的不是步骤多少，而是是否建立了**目标、行动、反馈、纠错和验收**之间的联系。

### 2. Agent 特有问题

| 问题 | 表现 | 应对 |
|------|------|------|
| 规划错误 | 步骤多却不通向目标 | 先定义验收，再检查计划 |
| 工具误用 | 参数错、选错文件/页面 | 检查调用参数和返回结果 |
| 状态丢失 | 忘记已完成、重复操作 | 维护任务状态和执行记录 |
| 错误累积 | 第一步错，后续放大 | 关键节点设检查点 |
| 无限循环 | 反复搜索/修复无退出 | 停止标准与重试上限 |
| 执行成功但目标失败 | 点了提交但业务未保存 | 验证最终状态，不只看工具反馈 |
| 权限与安全 | 超出授权、不可逆影响 | 权限边界与人工审批 |

### 3. Agent 不一定更好

只需简单解释 → 直接问模型更高效。需多来源搜索、大量文件、反复执行并验证 → Agent 才可能体现优势。同时增加成本、延迟、错误传播和权限复杂度。按任务决定，不为用 Agent 而用。

## 六、容易忽略但很重要的六个问题

1. **上下文管理**：维护可检查、可修订、可迁移的外部任务状态（目标、已确认事实、已做决定、未解决问题、下一步），不要依赖模型「应该记得」。
2. **验证**：表达流畅 ≠ 正确。警惕编造、把推测当事实、证据不足却明确。按风险分配验证成本（低/中/高）。
3. **研究方向管理**：分析越深入，若问题本身不重要，浪费越大。重大研究前先问：为什么值得解决？会改变什么决定？有没有更直接办法？哪些信息最可能改变判断？
4. **模型选择**：先检查定义、信息、是否需搜索/计算/执行、能否拆分验证；仍失败再换模型。多模型同意 ≠ 事实已证实。
5. **成本与时间**：额度、等待、复核、修改、返工、自动化收益。两分钟能做完的事不必花一小时设计复杂 Agent。
6. **人机分工**：AI 主导（整理、初稿、重复）；协作（复杂判断、权衡）；人工负责关键决策（重大资金、不可逆、安全与责任）。

## 七、整体处理方式：AI 问题解决与验证框架

### 第一步：判断所处阶段

- 还没想清楚 → 探索
- 知道大致目标但讲不清 → 定义指令
- 需深入研究、判断可靠与完整 → 研究与验证
- 希望真正动手 → Agent/执行
- 已有答案需判断是否真完成 → 审查与收束

### 第二步：按复杂度与风险选策略

| 任务情况 | 建议策略 |
|----------|----------|
| 简单、低风险、目标明确 | 直接回答，必要时快速检查 |
| 有歧义、需多角度 | 先探索，再定义问题 |
| 需外部事实或大量资料 | 研究、核查、归纳 |
| 需实际操作或多步骤 | 规划、执行、观察、验证 |
| 高风险或错误代价大 | 增加独立验证和人工审核 |

### 第三步：按失败类型修复（不要一味改 Prompt）

- 意图错误 → 修正问题定义
- 指令错误 → 修正表达和约束
- 知识错误 → 补充或核实资料
- 推理错误 → 拆分、计算或独立验证
- 工具错误 → 调整工具、权限或环境
- 验收错误 → 重新定义完成条件
- 闭环错误 → 检查实际结果，修复后重新验证

### 第四步：事先设定完成条件

必须解决哪些问题？哪些结论必须有证据？哪些未知可暂接受？交付什么？满足什么就停止？

## 八、如何系统学习

1. 先学会识别问题（目标定义、歧义、约束冲突、探索与收束）
2. 再理解模型能力边界（知识 vs 推理、幻觉、上下文、选型、何时搜索/计算/人工）
3. 接着建立验证方法（完整性、证据、反例、停止条件）
4. 最后学习 Agent（分解、工具、状态、反馈、恢复、权限、成本收益）

每阶段配合真实对照实验，而不只学概念。

### 三条原则

1. 不要把 Prompt 当成万能解法——先定位问题再决定改什么。
2. 不要把回答当成结果——区分计划、执行记录和经验证的最终状态。
3. 不要追求无条件的完整——先定义目标，再处理影响结论的关键不确定性，再按风险收益决定是否继续。

最终要培养的，不是越来越会提问，而是越来越能判断：当前问题是什么、AI 能做什么、哪里可能出错、怎样验证、以及什么时候已经足够。
