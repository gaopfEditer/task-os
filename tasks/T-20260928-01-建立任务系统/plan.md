# 计划

## 背景
任务和想法散落在聊天记录里，事后很难查到当时计划了什么、实际做了什么、学到了什么。需要一套固定结构，让 Bot 按指令改文件，历史可查询。

## 假设
- 做完后，任何任务都能通过 ID 定位到计划、执行、复盘
- 查询历史时 Bot 读 index.md 和 log.csv 回答，而不是凭记忆
- 复盘中的经验能沉淀为 README 里的系统规则

## 拆解
- [x] 创建目录结构和 README（状态机、操作规则）
- [x] 创建 index.md、log.csv 和 4 个模板
- [x] 用模板创建示例任务 T-20260928-01，并记录第一条执行
- [ ] 新建第 2 个真实任务
- [ ] 追加一条实践记录并改状态
- [ ] 测试查询：列出所有任务及每个任务最近一次执行
- [ ] 写本任务复盘，状态改为 reviewed

## 风险
- 风险：Bot 修改时另存副本，导致文件失联
  应对：README 明确禁止副本，所有修改改原文件
- 风险：状态只改了一处，index.md 与 task.md 不一致
  应对：状态变更必须同时改 task.md + index.md + log.csv
- 风险：查询时 Bot 凭记忆回答
  应对：规则要求先读 index.md 和 log.csv
