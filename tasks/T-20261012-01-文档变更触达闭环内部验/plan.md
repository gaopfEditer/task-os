# 计划

## 背景
核心六人群内刚定「文档变更 → 触达」内部验收卡，需落盘到 Task OS 便于追踪；链路为飞书文档变更 webhook 进入 msg-relay，bot 标识 `code`。

## 假设
- msg-relay 已具备多 bot 映射与 webhook 登记（见 2026-10-12 实践）
- 验收以可演示、可留痕为准，不要求前端或工作流产品化

## 验收（可勾选）
- [ ] **通知内容**：文档变更后经 msg-relay 收到通知，字段至少包含：doc_id、平台、变更时间、修订号或摘要
- [ ] **发出时间**：通知发出时间有记录（可与 webhook 接收时间区分）
- [ ] **人工跟进**：可记录跟进结果——有回应 / 无回应 / 响应时长
- [ ] **交付物**：变更日志样例、通知截图、跟进字段表（放 `artifacts/` 并在 execution.md 写路径）

## 拆解
- [ ] 代码大师：飞书 webhook → msg-relay `code` 原型与字段对齐
- [ ] 任务管家：按上表四项勾选验收
- [ ] 沉淀 artifacts 三样并更新 execution.md
- [ ] 验收通过后 task 标 `done`，复盘写入 review.md

## 风险
- 风险：飞书事件字段与 msg-relay 载荷不一致  
  应对：首条执行记录里固定样例 JSON，验收以样例为准
- 风险：两周内无足够外部同类需求  
  应对：按「出海判定」停扩，不强行产品化

## 时间盒
2026-10-12 至 2026-10-26（含两周需求观察窗口）
